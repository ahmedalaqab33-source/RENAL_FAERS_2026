# Strict synthetic record and resource contracts

`schema_registry.json` records exact required field sets, types, limits and normalization policy; runtime guards implement the same contract. Extra or missing fields, duplicate JSON keys, unsupported era/kind, nonfinite JSON, malformed UTF8 and invalid required IDs are rejected. Each physical JSONL line is accounted for; blanks are invalid rows, never silently dropped.

Legacy DEMO: era,kind,year,quarter,isr,case,i_f_cod,foll_seq. Modern DEMO: era,kind,year,quarter,report_id,case_id,case_version. Child rows: era,kind,year,quarter,parent_id,drug_seq,role. Year/quarter are plain integers, not booleans/floats. Legacy applies through2012Q3; modern from2012Q4 and2013–2025. These are deliberately scoped synthetic schemas reflecting source-era distinctions, not issuer certification or eligibility policy.

IDs are strings, at most512 Unicode characters/4096UTF8 bytes, nonempty, without surrounding whitespace or Unicode control categories. No normalization occurs. Legacy optional case/manufacturer fields may be null or blank and are reported as missing where applicable; FOLL_SEQ remains opaque and is never converted to CASEVERSION. Version and sequence are canonical positive decimal strings <=2147483647. Roles are explicit PS/SS/C/I. No field is an ingredient, patient or clinically validated case identity.

Parent coverage joins only exact(era,report-key). Distinct parent content contexts exclude year/quarter; identical content repeated across provenance periods is one context. Zero contexts=orphan; one=unambiguous content context; more than one=ambiguous. This is a new engineering contract, not historical parent eligibility or permission to attach drug fields. No rows are deduplicated, selected or repaired.

Modern case/version tuple diagnostics and report conflicts are global across chunks. Literal report_id==case_id||case_version is reported as a stored-string diagnostic only, not required for acceptance or interpreted as authenticated original PRIMARYID semantics. Legacy and modern namespaces never merge even when strings coincide. Cross-year counts describe stored strings, not independent cases/patients.

Input cap32MiB,100,000records,16KiB per line;batch1..4096. Python materializes at most one bounded batch plus one line; chunk receipts are streamed. SQLite cache target8MiB;SQLite process-global hard heap64MiB;page size4096/max65536pages;main DB cap256MiB. SQLite temporary grouping uses MEMORY under that heap limit; transient DB/journal file lengths are sampled and checked, not continuously reserved. Free-disk floor1GiB. Exceeding caps/time stops processing; no successful-looking partial result. Standalone CLI is the supported execution model because SQLite hard heap applies process-wide and is not restored for other connections.

Conservation: seen=valid+quarantined; successful full ingestion requires inserted=valid,expected_rows=seen;demo+drug=stored;orphan+unambiguous+ambiguous=drug. Controlled early failures explicitly record pending valid rows not committed; incomplete chunk receipts are never advertised as full coverage. Long-line fatal errors stop before accounting for the unconsumed line/suffix. No resume is implemented.

Physical duplicate metric means duplicate canonical parsed row values including year/quarter, not necessarily byte-identical source lines; raw chunk hashes preserve byte lineage separately. Fingerprints are computed per record and used internally for global multiset equivalence; literal identifiers are never exported in aggregate products. Output determinism applies to identical source bytes/batch/config on the tested runtime; logical metrics/multiset fingerprints remain stable across tested chunk sizes/order permutations while source/chunk lineage appropriately changes.
